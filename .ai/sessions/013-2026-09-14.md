## Decisions

- **The review's soft conclusions were tightened.** `models/MetricRecord.php` is dead, schema-incompatible code (inserts `year/quarter/value/note`, which do not exist in live `metric_records`) with no frontend consumer — the action is deletion, not reconciliation.
- **The gating dependency is the measure→account mapping**, not `metric_records`. New `metric_type_accounts` table bridges `metric_types` definitions to `company_accounts` (`domestic_revenue`/`export_revenue`/...).
- **Snapshot on verification is automatic, mandatory and atomic**, carrying periods, account bindings, completeness, and `calculation_version`.
- **Evidence is draft-editable, immutable once verified** — corrections revoke (with reason) or supersede; nothing verified is destroyed.
- **Verification = System Administrator or an authorized coach scoped to the company**, stated consistently across backend, UI and spec; recorder/verifier identities derived from authentication.
- **Decisions are events**, not achievements — excluded from counts and event-date labelled.
- **Results must show measured targets awaiting review**, not only manually-recorded achievements.
- **Financial-screen entry point added** (`Create target` / `Link existing target`) so the demo proves both entry points; final nav label is `Targets`, routes unchanged.
- **Measurement Contract** formalised: period-reference formats, company-scoped resolution, overlapping-binding dedup, missing-account/month semantics, increase/decrease/maintain formulas, explicit tolerance, `target == baseline` guard, and `calculation_method` restricted to the implemented `period_total`.

## Decisions

- **Remove the mutating method entirely** (rather than gate it behind a flag) so task completion can never again declare an outcome achieved.
- **Return task completion as an additive `task_progress` field** on `getById()` and the task mutation endpoints — preserves existing API consumers while giving the frontend a read aggregate.
- **`reorder.php` unchanged** — ordering does not change completion counts, and its response is an array (adding a sibling key would break compatibility).
- **No automatic repair** of historically auto-completed targets; a detection query is documented for manual review.
- **`percent` is `0.0` (float) when there are no tasks**, distinct from an error state.
- **Phase 3 constraints hardened per reviewer feedback:** row presence only proves a record exists (zero-filled months hide completeness), and null-`account_id` rows cannot be attributed by account type alone — exclude and report them.

## Decisions

- **Two delivery sprints, preceded by discovery** — packaged as three `.ai/sprints/` documents; discovery has
  its own exit criteria so no implementation begins on assumptions.
- **A site visit is a Session.** Add `session_type='site_visit'` and attach a structured report
  (`session_visit_reports` + items + sign-offs + versions) inside `capabilities/sessions`. Reuse facilitator,
  participants, attendance, calendar event, Google Meet and `session_entity_links`; invent nothing.
- **Needs Analysis becomes a first-class normalized capability** (`capabilities/assessments`), not a node or a
  form. Framework is versioned data; scoring is a pure service; finalisation writes an immutable version.
- **Interventions link outward.** Agreed actions are `gps_target_tasks`; outcomes reuse Achievements; the
  assessment never mutates those domains.
- **Provenance is fixed.** `gps_target_sources` gains real `assessment_id` + `assessment_finding_id` columns so
  `source_type='assessment'` stops being a label with no record.
- **Missing ≠ not applicable.** The score is a number and applicability is a separate flag; the denominator
  counts applicable weighted criteria only. Legacy `consolidated_assessment` (>100% progress) is flagged but
  not migrated.
- **Snapshots freeze truth.** Issued/finalised documents preserve exactly what was rendered; live edits never
  rewrite history; `incubator`-visibility notes are excluded from every snapshot and export.
- **Funding stays four separate states** (committed / paid / delivered / utilised) and is derived on read,
  never stored on a report.

## Discovery D.1–D.9 — evidence package (2026-09-25, continued)

Ran the discovery field trace as a code-verified reconnaissance (read-only, no files in the app touched) and
appended the **Discovery Evidence Package** to `.ai/sprints/Discovery-011-012.md`. Wording correction applied:
the diagnostic PDF is now labelled **"template/example content — not verified beneficiary data"** (we have not
established it belongs to a real beneficiary), and DS Corp `[TBC]` fields are treated as unresolved.

### Key evidence found

- **Company fields**: two disjoint editors. The current shell cannot write `description`, `vat_number`,
  `postal_code`, compliance flags, turnover or employees; `description` is writable **only** via legacy
  `update-company.php`, so the canonical nature-of-business field is orphaned from the capability.
- **Vision/mission** lives in `company_vision` nodes with **zero PHP ownership**, is absent from
  `get-overview`, and its editor is **unreachable** (Strategy tab button commented out; shell has no tab).
- **Funding**: the four states exist for committed/paid/delivered but **`utilised` has no field anywhere**;
  DS Corp has **no `companies` row** (only a `grant_application` node with `company_id NULL`), so the report's
  narrative is the only record; `company_purchases` table and `company_purchase` node are semantic twins with
  no shared row id (double-count hazard); `parent_id` keying is ambiguous when `company_id` is null.
- **Visit history**: no actual-visit-date field exists; `sessions.started_at` is a workspace lifecycle instant,
  not a visit date; no relational sign-off table and no issued-document snapshot exist.
- **Scoring**: the legacy >100% defect is real (`questionnaire.service.ts:389`, denominator 25 vs 26
  questions); the form system has rating/scale field types but **no scoring engine**; the requested
  "Critical Vulnerability" wording does not exist — adopted the D2 1–5 wording as the canonical scale.
- **Traceability**: `gps_target_sources` has **no** `assessment_id`; `session_entity_links.entity_id` is
  polymorphic with no FK and its actor-reachability claim is **not implemented**.
- **Migrations**: #26 free; **#27 was assigned to two files** — corrected to **#27 + #28** with the phased
  naming convention instead of the patch `b` suffix.

## Decisions

- **Measures come from bindings.** The binding dropdown lists only metric types that have `metric_type_accounts` bindings (via the new endpoint) because only those can be derived; the rest would always be `no_accounts`.
- **Backend owns validation.** The equal baseline/goal and zero-baseline percentage-tolerance cases are surfaced as `invalid_definition` from the measurement response; the UI does not pre-empt them. `maintain` without a tolerance is rejected by `attach` (400).
- **No optimistic state on binding.** After save/remove, the target, binding and actual are reloaded from the server.
- **Achievements lifecycle mirrors Results.** Draft authoring for any company user; verify/reject/revoke/supersede gated by `isSA()`; a 409 reloads and shows the server message, leaving the record unchanged.
- **Task editor is inline**, consistent with the modal rules; `task_progress` still comes from the backend and task activity never mutates the parent target.

## Decisions

- **Capability layer, not `api-nodes`.** The task said not to assume `api-nodes` because it was suggested. Inspection showed `capabilities/` + `api/` is the newer convention, so the calendar follows it — with `AuthGuard` added, since the existing capability endpoints had no auth.
- **All-day = DATE, timed = UTC DATETIME + timezone.** Enforced by a DB CHECK, the PHP validator, and the Angular mapper. An all-day date is never midnight UTC.
- **`company_id = NULL` is a scope, not a bypass.** Reads include system-wide events everywhere; only administrators may write them, and they may not carry links.
- **Server-derived identity.** Actor, tenant, creator and timestamps never come from the browser.
- **Optimistic concurrency + idempotency.** `version` rejects stale writes (409); `client_token` makes retried creates safe.
- **Soft delete ≠ cancel.** `deleted_at` hides; `status='cancelled'` keeps visible.
- **Mock data discarded, not migrated.** Phase 1 localStorage events were never imported into the database.
- **Tenant resolution isolated.** The platform is effectively single-tenant (`tenant_id` defaults to 1); `CalendarAccessPolicy::tenantId()` is the single place that decides, so a future multi-tenant map changes only there.

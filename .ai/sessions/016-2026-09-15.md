## Decisions

- **Five completeness states**, precedence `no_accounts → partial_coverage → incomplete → unknown → complete`. `unknown` is any all-zero-only row (cannot confirm capture); `complete` requires a populated row (zeros confirmed) — so **zero-filled legacy rows are never labelled complete**.
- **Unresolved rows are excluded from subtotals and reported** via `unresolved_rows`; their presence makes a result **non-authoritative** and blocks achievement eligibility.
- **Partial coverage is surfaced**, never hidden: if only some required bindings resolve, the subtotal is explicitly partial revenue, not combined revenue.
- **Goal semantics**: baseline = baseline-period subtotal, actual = target-period subtotal, goal = `gps_target_metrics.target_value`. (The initial mis-use of the target subtotal as the goal was a real bug caught by fixtures.)
- **Authority gating**: progress computed only when both periods are `complete`; `authoritative` additionally requires zero unresolved rows in both.
- **`custom` periods limited to a single financial year**; multi-FY ranges are `invalid_period`.
- **`maintain` + percent tolerance with zero baseline** → `invalid_definition` (a percentage of zero is undefined).
- **No backfill / no repair** of the local financial data, even though most of it cannot produce an authoritative result yet.

## Decisions

- **The completion write is double-guarded** (lease token + local event version). After any remote response a stale worker cannot overwrite newer local state; a version mismatch records `update_pending` instead.
- **PATCH sends only managed fields.** No `conferenceData` and no `id`, so Google preserves the conference and unrelated provider fields. Attendees are always sent (the local Session is the truth); `sendUpdates` is `all` only when attendees exist.
- **A PATCH that returns no conference info must not downgrade a meeting to pending.** The service retains the last known conference state/URL.
- **Conflict stores two etags, never a snapshot.** `remote_etag` + `conflict_at` are enough for Phase 5 to say "changed externally" without copying attendee/description data.
- **Reschedule propagation is explicit (`sync`), not an automatic cascade.** `onEventChanged` is a no-op so a burst of edits does not email attendees; only cancellation cascades automatically.
- **A new publication generation on republish.** The deterministic id embeds the generation and the conference request id is regenerated, so a tombstoned Google id is never reused.
- **The cancellation reason is internal.** It is stored locally and never reaches the Google payload or the sync row.
- **HTTP 410 is mapped to the same `not_found` reason as 404** so cancellation/unpublish treat both as already-absent success.

### Defects found and fixed during Phase 4 testing

1. `GoogleCancelHook` was included before its interface in `_bootstrap.php`, causing "Interface not found". The hook interface now loads before the implementation.
2. The fake patch fabricated a 412 whenever it had no knowledge of an event (a fresh instance per HTTP request). It now only conflicts against a KNOWN etag, keeping the `__stale__` fixture for the Phase 1 test.
3. A meeting's conference state was downgraded to `pending` after a reschedule because the PATCH carries no conference data. The service now retains the last known conference state on such a ref.
4. `last_google_event_id` was being nulled on republish; it now coalesces so the audit id survives.
5. The Phase 4 HTTP test read the event version from `get.php`'s `data` envelope; that endpoint returns the DTO at the top level.

## Decisions

- **`listBySwotItem` mirrors `listByTarget` symmetry** — a source→target listing should return the *target* row, not the link row, and expose the link id as `source_id`. This is what the provenance join (`listByTarget` returning `swot_description`/`swot_category`) already did, so the fix restores symmetry rather than adding a new shape.
- **`source_id` is the link id; `id` is the target id** — removes the previous ambiguity (`t.id && t.swot_item_id ? t.id : 0`) that would have deleted the wrong `gps_target_sources` row.
- **`nodes` is treated as dual-purpose (archive + activity log)** — count comparisons for “nodes untouched” must exclude `type='activity_log'`; the meaningful figure is the non-log node count (1901). Documented so future QA does not misread page-view logging as data mutation.
- **`/*.png` ignored at repo root only** — the sole tracked PNG lives under `api-incubator-os/api-nodes/upload/uploads/`, so a root-scoped pattern is safe.
- **Company 10 demo data left as-is** per explicit instruction (no reset to pristine 1/3 @ 33%).

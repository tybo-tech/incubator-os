## Decisions

- **`account_id` semantics**: bindings are global to the measure; `account_id = NULL` resolves by `account_type` within the requested company; a pinned `account_id` matches only if it belongs to that company, otherwise it is ignored. Keeps one binding table without adding `company_id`.
- **`account_id_key` generated column** (`COALESCE(account_id, 0)`) so the unique key treats NULL account ids consistently (MySQL UNIQUE treats NULLs as distinct) — mirrors the `swot_analyses.current_company_id` generated-column pattern.
- **Guarded, idempotent migration** using `information_schema` + `PREPARE` for each column add (MySQL 8.0.43 does not reliably support `ADD COLUMN IF NOT EXISTS`).
- **`calculation_method` enum is `period_total` only** — no unimplemented methods are selectable.
- **Fixed the latent `attach()` bug** rather than working around it, since Phase 2–3 depend on metric writes.
- **Measured financial semantics before assuming**: "missing" vs "explicit zero" is decided by **row presence**, not NULL months (`total_amount` COALESCEs NULL→0 and must not be used for completeness); `account_id` is often NULL (105/179), so resolution must go through `company_accounts` by type.
- **Endpoint guard = `auth_is_migration_admin`** (System Administrator), consistent with measure bindings being an administrative mapping.

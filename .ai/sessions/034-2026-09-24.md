## Decisions

- **Three separate signals, never one blurred badge.** The connection chip, the published flag, and the match/`upToDate` flag are independent. A colour is never the only cue — every state pairs an icon with text.
- **Ownership is per-connection, not per-role.** `ownedByViewer` is derived from the stored `connection_id`, and both the UI and the service refuse a non-owner's sync/unpublish — even for an admin.
- **Presentation context is derived, not stored.** `attendeeCount`/`willSendInvitations`/`isMeeting`/`upToDate` are computed by `present()` from the local event and the deterministic attendee list; nothing new is persisted and Google is never called.
- **`upToDate` is the honest "does Google match?" answer.** A local edit flips it false while the projection stays `synced`; the UI then shows "Changes not yet synced" without claiming a sync.
- **Publishing is never automatic.** A form edit does not sync; the user presses `Sync changes`. The confirmation always states the attendee/invite/Meet consequences first.
- **Conflict has no destructive control.** Only `Open Google Calendar` is offered; Retry (which would re-412) and Overwrite/Use-Google-version are withheld until a real resolution command exists.
- **The conflict write preserves the known links.** A divergence must not erase the Meet/Google URLs, or the conflict view loses its one safe action.
- **Remove vs Disconnect vs Cancel stay distinct.** "Remove from Google Calendar" retains the local event/Session/audit and allows a new publication generation.

### Defects found and fixed during Phase 5 testing

1. **Conflict wiped the Google/Meet links.** `handleSyncFailure` wrote a conflict row without `google_event_url`/`meet_url`, so the UI could offer neither Open-in-Google nor Join-Meet. Fixed to preserve the last known links; added a Phase 4 assertion (`92/92`).
2. **Publish was hidden for unpublished events.** The management gate used `ownedByViewer`, which is false before a mapping exists. Fixed to gate on the ACTIVE mapping; added an Angular spec.
3. **Duplicate "Open" action under conflict.** The generic links block plus a conflict-specific link produced two identical actions; removed the duplicate.

# Session 021

Date:
2026-09-16

## Goal

Give every popup the same layout contract: **header and footer stay fixed; only the body scrolls** when the content is tall. Do it through the shared popup styles (so it applies everywhere at once) and document the contract. No legacy screen changes.

---

## Completed

- Fixed the shared `.sw-modal` styles in `src/styles.scss`:
  - `.sw-modal-card` is now a flex column (`display:flex; flex-direction:column; overflow:hidden`) capped at `max-height:92vh` — the card itself no longer scrolls.
  - `.sw-modal-head` / `.sw-modal-foot` are `flex:0 0 auto`; `.sw-modal-body` is `flex:1 1 auto; min-height:0; overflow-y:auto`.
  - This fixes the normalized **Results / Targets / SWOT** popups with no template changes.
- Applied the equivalent Tailwind contract to the remaining current surface popups:
  - `financial-target-entry` — card `flex flex-col max-h-[90vh] overflow-hidden`; header/footer `shrink-0`; body `flex-1 overflow-y-auto min-h-0`.
  - `financial-indicators` dialogs (`financial-form`, `view-dialog`, `import-dialog`, `request-dialog`) — same treatment.
- Documented the contract in `AGENTS.md` under a new **"Popup layout — fixed header/footer, scrollable body"** subsection, including the `.sw-modal` class contract and the Tailwind equivalent.
- Confirmed legacy financial-shell dialogs were left untouched (client: skip legacy).

## Decisions

- **Shared styles over a new wrapper component.** The codebase already has a shared popup primitive (`.sw-modal` classes / tokens scoped per page), so enforcing the layout there fixes every existing popup at once and avoids a risky template refactor of the three SWOT/Targets/Results dialogs. A lightweight `app-modal` wrapper remains an option if we later want structure enforced at the type level.
- **Tailwind dialogs use the same contract** (`flex flex-col` + `shrink-0` head/foot + `flex-1 overflow-y-auto min-h-0` body), documented so new Tailwind popups comply.
- Legacy financial-shell dialogs deliberately untouched.

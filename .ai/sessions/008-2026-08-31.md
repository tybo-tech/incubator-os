## Decisions

- **Auth is session-based, not token-based** — reused the existing `$_SESSION['user_id']` pattern from `api-nodes/user/invite-user.php:15` / `validate-session.php:13` (session cookie `None`/`Secure`/`Httponly`). No new auth mechanism introduced; admin = `System Administrator` or `Coordinator` can access any company, others are scoped to `user.company_id`. This matches the current frontend `AuthService` which uses `withCredentials:true`.
- **Generic `auth_enforce_request()` that reads body fallback** — because our patch inserts auth before `$input` is defined in some files, the guard now re-reads `php://input` JSON if `$input` is empty and method is POST/PUT/PATCH. This makes insertion order irrelevant and ensures `company_id` in the JSON body is still checked.
- **Savepoint per node, not full-batch rollback** — review suggested either savepoint per node or full rollback for the sample. We chose savepoints as described in the review (`SAVEPOINT migrate_node / ROLLBACK TO SAVEPOINT`), which prevents partial commits while still allowing the batch to continue for the next company. For the strict “fail whole transaction on any error” mode, the savepoint could be replaced by a single throw — the current per-node savepoint is the more permissive, review-preferred option.
- **Cross-company link is a hard error, not a silent ignore** — `assertSameCompany()` throws, which the endpoint surfaces as 400. This is intentional; a mentor should not be able to wire Company A’s target to Company B’s weakness.
- **Legacy_unlinked is deleted, not converted** — on first real link, the placeholder row is deleted. If a target later gets multiple real links, the placeholder is already gone, so the target cleanly transitions from “unlinked” to “linked”.
- **Task progress is derived, not dual-maintained** — `recalcTaskProgress()` writes to `manual_progress_percentage` for convenience even though the canonical progress is `completed/total*100`. This keeps `dashboardCounts` working without a separate computed column, but the value is now derived when `progress_mode='tasks'` (and ignored when `manual`).
- **Manual update now sets `completed_at`** — previously a manual update with `status=completed` left `completed_at` NULL; now it mirrors `GpsTarget::update()` behavior (set on completed, clear otherwise).

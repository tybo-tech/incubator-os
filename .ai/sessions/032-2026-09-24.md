## Decisions

- **Deterministic Google event id** (`inc` + hex tenant + hex event) instead of a stored id. Re-inserting the same id makes Google answer 409, so a remote success followed by a local failure recovers without duplication. No new column needed.
- **Conference status is independent of sync status.** A `pending`/`failure` conference leaves the event synced but never `fullySynced`, so the UI and any caller can distinguish "event created" from "Meet room ready".
- **A short local lease, not a transaction, guards concurrency.** Reserve (tiny transaction) → Google call (no transaction) → complete (tiny transaction, lease-token guarded). Stale leases are taken over so a crash self-heals.
- **`sendUpdates=all` only when there are attendees**, so a generic event sends no unnecessary email.
- **Content-safe description:** Session subject + authenticated Incubator OS link only. The mapper cannot see notes/SWOT/financial fields.
- **Attendees come only from the linked Session.** Locks out attendee inference from company users or the assignee (amends Architecture Decision 6).
- **Refresh at most once per publish**; a 401 after that refresh stops the call, and `invalid_grant` flips the connection to `needs_reconnect`.

### Defects found and fixed during Phase 3 testing

1. The fake client created a fresh event on every insert, so a "response lost" retry could not be distinguished from a real duplicate. It is now stateful and honours the deterministic id, answering duplicate/`getEvent` like Google.
2. The publish test initially asserted the internal participant's *snapshot* email; the resolver prefers the live user email, which is correct. The fixture was corrected.
3. PowerShell 5.1 mangles inline JSON through `curl.exe --data-binary`; the HTTP suite now passes bodies via a UTF-8 file. It also treats PHP's `\/` JSON escaping in the URL assertions.

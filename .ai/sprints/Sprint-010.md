## Objective

Give the calendar a **server-side, per-user Google Calendar connection** so a user can publish an Incubator OS calendar event to their own Google Calendar, **automatically receive a Google Meet link**, invite participants, and keep the Google event in step when the local event is rescheduled or cancelled.

This sprint delivers:

1. **Google OAuth 2.0** (web-server flow) owned entirely by the PHP backend — authorization URL, callback, code exchange, refresh, revocation. Angular never sees a client secret, access token or refresh token.
2. **Automatic Google Meet links** generated by the Google Calendar API `conferenceData.createRequest` on a normal calendar event — no separate Meet API call.
3. **Outbound synchronization** — publish once, then reschedule/cancel propagates to Google with optimistic concurrency (`If-Match` / `etag`).
4. **Participant invitations** — the linked Session's participants (internal users + external attendees) become Google `attendees`, with `sendUpdates=all`.
5. **Connection lifecycle in the UI** — connect, connected, reconnect-required, disconnect — plus per-event publish / sync / remove controls and a Join-Meet link.

Incubator OS remains the **operational source of truth**. Google is a **projection**: local writes always win, Google is never read back into the local event, and a failed Google call never blocks a local operation.

**Explicitly not this sprint:** the Google **Meet API** (conference records, participants, attendance, recordings, transcripts). That is deferred to a later sprint (see *Future Modules (Reserved)*).

### Invariants

1. One calendar event has **at most one** Google sync row (`UNIQUE (calendar_event_id)`).
2. One user has **at most one** Google connection (`UNIQUE (user_id)`).
3. A sync row always references a **live** local event and a **live** connection.
4. Tokens are **encrypted at rest** and are **never** returned to the browser, included in a response DTO, or written to a log.
5. **Local is source of truth.** A Google write never silently overwrites local data.
6. Only a **server-side** call drives Google. The browser never receives a Google token, client secret, or `refresh_token`.
7. A published event's `google_event_id` and `meet_request_id` are **stable**; a retried publish never creates a second Google event or a second conference.
8. The local **all-day** `end_date` is **inclusive**; Google's `end.date` is **exclusive** — the adapter adds one day on the way out and the round-trip preserves the local inclusive date.
9. A revoked or expired refresh token moves the connection to **`needs_reconnect`**; no further sync is attempted until reconnected.
10. Cancelling a local event (directly or through Session cancel) cascades a **best-effort** Google cancel; a Google failure never blocks or fails the local cancel.
11. `tenant_id`, actor, timestamps and connection ownership are **server-derived**; no Google identifier is accepted from the browser.

## Architecture Decisions

1. **Google is reached over the Google REST APIs with cURL**, not `google/apiclient`/Composer. The required surface is small (token endpoint, userinfo, events insert/patch/delete, revoke), the codebase has **no Composer autoloader** for the main app, and `helpers/Mailer.php` already establishes cURL as the HTTP precedent. Introducing Composer to a hand-wired `include_once` application is a larger architectural change than this sprint warrants.
    
    > The conversation suggested `composer require google/apiclient`. That remains valid for a future sprint; it is deliberately **not** used here. A single `GoogleApiClient` interface isolates the choice so it can be swapped later without touching callers.

2. **A new capability pair** `capabilities/google-calendar/` + `api/google-calendar/` (feature name `GoogleCalendar`, `dependsOn: ["Calendar", "Companies", "Users"]`). Google is not added to `capabilities/calendar`, keeping the frozen calendar domain free of OAuth concerns.

3. **Endpoints follow the repository convention** (`queries|commands/{file}.php`, `?id=`, `action` query params, `CommandResult` envelope) — **not** the REST-style `/api/calendar-events/{id}/publish/google` sketch in the conversation. The REST sketch and this convention are equivalent in intent; the convention wins so the capability matches Calendar/Sessions.

4. **A dedicated `google_event_sync` table**, rather than new columns on `calendar_events`, so the frozen calendar schema and its CHECK constraint are untouched.

5. **Connections are per user** (one Google account per user). Publishing uses the **acting user's** connection; the resulting sync row stores `connection_id`, so a **different authorized user may later sync/reschedule** using the original publisher's connection (server-side). This avoids "only the original publisher can ever reschedule".

6. **Attendees come from the linked Session** when one exists (internal participants with an email + external attendees with an email, deduped); otherwise from the event's `assignee` when it resolves to an email. No Session → no attendees is valid (publish still succeeds, with a warning).

7. **Meet conference only for `meeting` category events.** Any accessible, non-deleted event may be published to Google Calendar, but `conferenceData.createRequest` is added only when `category = meeting`. `conferenceSolutionKey.type = hangoutsMeet`.
8. **Secrets live in a gitignored `config/google.local.php`**, loaded by a committed `config/google.php`. If the provider is present but the local file is missing/incomplete, the capability **fails closed** — every endpoint returns `503` `GOOGLE_NOT_CONFIGURED` and the UI shows a clear message. No Google secret is ever committed or added to the deployment upload manifest.
9. **Outbound only.** There is no inbound Google → Incubator synchronization, no watch channels and no webhooks in this sprint. A Google-side edit surfaces as a `conflict` (etag mismatch), never as an overwrite.
10. **Signed, stateless OAuth `state`.** The state is an HMAC-signed, time-limited, actor-bound token (no database table). The callback requires the state's `userId` to match the session's user, which prevents login-CSRF. Google's `code` is single-use.
11. **A `GoogleEventSyncHook` interface** is declared in `capabilities/calendar` (no-op default) and implemented by `capabilities/google-calendar`; the **calendar cancel/delete endpoints** wire the real implementation. `capabilities/calendar` therefore never includes a google-calendar file.
12. **The Google client is an interface** (`GoogleApiClient`) with `CurlGoogleApiClient` (production) and `FakeGoogleApiClient` (local tests, selected by `GOOGLE_FAKE=1`). All backend tests are deterministic and never touch the network.

## Security Contract (locked)

* The OAuth client secret, access token and refresh token are **never** present in any JSON response, error message, `CommandResult`, log line or `error_log` entry.
* Tokens are stored with **AES-256-GCM** (`openssl_encrypt`), key from `config/google.local.php` (32 bytes). Random 12-byte IV per record; authentication tag stored with the ciphertext. A failed tag check is a hard failure, never a silent empty token.
* `state` is HMAC-signed, bound to `userId`, single-use within a short expiry (10 minutes), and verified before any code exchange.
* The OAuth **redirect URI is registered exactly** as `{APP_URL}/api/api/google-calendar/commands/callback.php` (local `http://localhost:8080/api/api/google-calendar/commands/callback.php`).
* Disconnect performs a best-effort `POST https://oauth2.googleapis.com/revoke` and deletes the connection row.
* Client ID / secret / encryption key are supplied by the operator on the server; the agent never handles their values.

## API Contract

Base `{ApiBase}api/google-calendar`.

### Queries

| Method | Endpoint | Returns |
| --- | --- | --- |
| `GET` | `queries/connection.php` | `GoogleConnectionResponse` — `status`, `googleAccountEmail`, `calendarId`, `connectedAt`, `needsReconnect`. **Never** tokens. `null` connection = `{ status: "disconnected" }` |
| `GET` | `queries/event.php?id=` | `GoogleEventSyncResponse` for one calendar event (status, meet URL, Google event URL, last sync, last error). `null` when not published. Requires event access. |

### Commands

| Endpoint | Body | Purpose |
| --- | --- | --- |
| `GET` | `commands/callback.php?code=&state=` | **Google-initiated browser redirect.** Verifies state, exchanges `code`, fetches the account email, encrypts + stores tokens, then `302` to `{APP_URL}{returnTo}?google=connected`. Errors redirect with `?google=error&reason=...`. *Placed under `commands/` because it writes (it is a command); the `GET` verb is fixed by Google and is the only deviation.* |
| `commands/connect.php` | `{ returnTo }` | Build the authorization URL (offline access, `prompt=consent`, signed state). Returns `{ authUrl }`. **No secret returned.** `returnTo` is validated as a safe in-app relative path |
| `commands/disconnect.php` | — | Best-effort revoke + delete the actor's connection |
| `commands/publish.php?id=` | `{ version }` | Create the Google Calendar event (+ Meet conference for `meeting`) and persist a `google_event_sync` row. Idempotent: an existing row returns the existing Google identifiers |
| `commands/sync.php?id=` | `{ version }` | Push local changes to Google (`PATCH`, `If-Match` etag). Status `cancelled` → `DELETE` with `sendUpdates=all` |
| `commands/unpublish.php?id=` | `{ version }` | Remove the Google event and set the sync row `detached` |

Server-derived, never accepted from the browser: actor, tenant, connection ownership, Google identifiers, timestamps. `company_id`/`id` are **target scopes only**.

### HTTP outcomes

| Status | When |
| --- | --- |
| `200` / `201` | Success (`CommandResult` envelope) |
| `401` | No session, or Google returned `invalid_grant` (also flips the connection to `needs_reconnect`) |
| `403` | Actor cannot access the target event / not the connection owner |
| `404` | Event or sync row not found |
| `409` | `ALREADY_PUBLISHED`, `NOT_PUBLISHED`, `SYNC_CONFLICT` (etag mismatch), stale `version` |
| `422` | Validation failure (`{error, errors}`) |
| `503` | `GOOGLE_NOT_CONFIGURED` — provider present, local credentials absent |

| Connect / disconnect **own** Google account | ✅ | ✅ |
| View **own** connection status | ✅ | ✅ |
| View another user's connection | ❌ never | ❌ never |
| Publish / sync / unpublish an event (tenant-wide) | ✅ | ❌ |
| Publish / sync / unpublish an event in own company | ✅ | ✅ |
| View an event's sync status / Meet link | ✅ | ✅ (own company) |
| Read any token | ❌ never (no endpoint exposes it) | ❌ never |

## Definition of Done

The implementation is complete when:

- [ ] Migration run order #22 applies twice safely and alters no existing table.
- [ ] `config/google.php` fails closed when the local credentials are absent (`503 GOOGLE_NOT_CONFIGURED`); the agent never handles secret values.
- [ ] Tokens are encrypted at rest (AES-256-GCM) and appear in **no** response, log or error message.
- [ ] OAuth connect → callback → disconnect works end-to-end; bad/expired/other-user `state` is rejected.
- [ ] `needs_reconnect` is set on `invalid_grant` and blocks further sync with a clear UI recovery path.
- [ ] A `meeting` event publishes with an automatic Google Meet link; a non-meeting event publishes without one.
- [ ] All-day events preserve inclusive local dates (Google exclusive `end.date`); timed events preserve their IANA wall time, including across DST.
- [ ] Publishing is idempotent — no duplicate Google event and no duplicate conference, ever.
- [ ] Reschedule propagates to the same Google event; cancel (including via Session cancel) propagates best-effort and never blocks the local cancel.
- [ ] A Google-side edit produces `409 SYNC_CONFLICT` and marks `conflict`; local data is never silently overwritten.
- [ ] Session participants (with emails) become Google attendees; invites are sent (`sendUpdates=all`).
- [ ] Authorization: publishing/syncing requires event access (SA tenant-wide, others own company); tokens are owner-only and never exposed.
- [ ] `capabilities/calendar` has no dependency on `capabilities/google-calendar` (interface + endpoint wiring only).
- [ ] Angular: connection chip, publish/sync/remove controls, Join-Meet and Open-in-Google links, conflict/failed recovery, query-param handling, popup contract respected, zero console errors.
- [ ] `api-incubator-os/tests/GoogleCalendar.ps1` passes with `GOOGLE_FAKE=1` without network access.
- [ ] Docs: `docs/google-calendar-api.md`, `docs/calendar-api.md` update, sprint + session records, migration README row, deployment package + rollback additions, and the Google Cloud Console / verification guidance.
- [ ] Production build is clean with no new budget warning.
